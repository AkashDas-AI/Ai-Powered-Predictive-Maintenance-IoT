## 2. Benchmark / Simulation Status

> [!IMPORTANT]
> The AI4I 2020 dataset is a **synthetic benchmark dataset reflecting real industrial milling machine operations**, generated by Stephan Matzka. It is **not** a direct feed from live physical production telemetry. It was constructed using physical equations, realistic random walks, and empirical process parameters to mirror real failure dynamics.

---

## 3. Dataset Dimensions & Schema

- **Total Records (Rows)**: 10,000
- **Total Attributes (Columns)**: 14 (3 metadata identifiers, 5 operating telemetry features, 1 primary binary target, 5 failure-mode indicators)
- **Missing Values**: 0 (0.0% across all 14 columns)
- **Duplicate Rows**: 0

### Column Specifications

| Column Name | Data Type | Physical Unit | Description & Generation Rule |
| :--- | :---: | :---: | :--- |
| `UDI` | `int64` | Dimensionless | Unique row identifier ranging from 1 to 10,000. |
| `Product ID` | `object` / `string` | Dimensionless | Consists of quality variant letter (`L`, `M`, `H`) followed by a 5-digit variant serial number. |
| `Type` | `object` / `string` | Dimensionless | Machine variant representing product quality: **L** (Low, 50% of fleet), **M** (Medium, 30%), **H** (High, 20%). |
| `Air temperature [K]` | `float64` | Kelvin ($K$) | Ambient temperature simulated via normalized random walk ($\mu \approx 300\text{ K}$, $\sigma = 2\text{ K}$). |
| `Process temperature [K]` | `float64` | Kelvin ($K$) | Process temperature generated via random walk ($\sigma = 1\text{ K}$) added to ambient air temperature plus 10 K baseline. |
| `Rotational speed [rpm]` | `int64` | RPM | Spindle rotational speed calculated from a constant power of 2,860 W with superimposed Gaussian noise. |
| `Torque [Nm]` | `float64` | Newton-meters ($\text{N}\cdot\text{m}$) | Mechanical torque normally distributed around 40 Nm ($\sigma = 10\text{ N}\cdot\text{m}$), bounded at zero (no negative torque). |
| `Tool wear [min]` | `int64` | Minutes | Cumulative machining active time. Variants H/M/L add 5/3/2 minutes of wear per workpiece. |
| **`Machine failure`** | `int64` | Binary (`{0, 1}`) | **Primary target variable**: `1` indicates an equipment failure event at this timestep, `0` indicates normal operation. |
| `TWF` | `int64` | Binary (`{0, 1}`) | **Tool Wear Failure**: Occurs when tool wear exceeds wear limit thresholds (between 200 and 240 minutes). |
| `HDF` | `int64` | Binary (`{0, 1}`) | **Heat Dissipation Failure**: Triggered when temperature delta ($\Delta T = T_{\text{process}} - T_{\text{air}}$) is $< 8.6\text{ K}$ and rotational speed is $< 1,380\text{ rpm}$. |
| `PWF` | `int64` | Binary (`{0, 1}`) | **Power Failure**: Generated when mechanical power ($P = \tau \cdot \omega$) falls outside the safe operating window of $[3,500\text{ W}, 9,000\text{ W}]$. |
| `OSF` | `int64` | Binary (`{0, 1}`) | **Overstrain Failure**: Triggered when product of tool wear and torque exceeds variant-specific mechanical stress limits. |
| `RNF` | `int64` | Binary (`{0, 1}`) | **Random Failure**: Uncorrelated failure mode simulated with a $0.1\%$ independent probability. |

## 5. Observed Anomalies & Data Nuances

1. **Unattributed Failures (9 instances)**: There are exactly 9 instances (UDIs: 1438, 2750, 4045, 4685, 5537, 5942, 6479, 8507, 9016) where `Machine failure == 1` but **none** of the five specific failure modes (`TWF`, `HDF`, `PWF`, `OSF`, `RNF`) is flagged (`sum == 0`). In the original generator script, these represent unclassified failure dynamics or unrecorded modes.
2. **Non-Failure Random Triggers (18 instances)**: There are 18 instances where random failure mode `RNF == 1` was simulated, yet the overall system flag `Machine failure == 0`. Only 1 instance exists where `RNF == 1` and `Machine failure == 1` (UDI 3612, which also experienced a `TWF`).
3. **Compound Failures**: Certain operating conditions trigger multiple failure modes simultaneously (e.g., high torque and speed envelope triggering both `PWF` and `OSF`).
4. **Label Integrity & Prediction Contract Policy**: In accordance with rigorous data science standards, **original labels are strictly preserved without alteration**. We do not overwrite `Machine failure` or synthesize an artificial target from the failure mode flags. Because the upstream simulation code is proprietary, the 9 unattributed cases and 18 non-failure random flags remain documented as unresolved artifacts of the synthetic generation process.

## 6. Known Limitations

- **Not Real-Time Stream**: The records represent discrete cycles rather than continuous sub-second waveforms (e.g. raw vibration acceleration traces).
- **Synthetic Physics**: Sensor values follow explicit mathematical approximations rather than physical sensor drift, sensor degradation, or environmental electromagnetic interference.
- **Independent Samples Assumption**: While sequential `UDI` exists, the samples behave more like independent operating trials than continuous time-series degradation paths for a single serial machine.
